# NAME SYNERGY — 제품 요구사항 (PRD)

- 버전: PHASE 1 MVP
- 상태: 기획 확정, 구현 전
- 최종 수정: 2026-11-08

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 제품명 | NAME SYNERGY |
| 슬로건 | Two Names, One Connection. |
| 한 줄 정의 | 두 사람의 이름을 규칙 기반으로 비교해 이름 조화 지수, 관계 유형, 관계 스토리를 보여주는 웹 서비스 |
| 대상 관계 | 연인, 부부, 친구, 가족, 동료, 반려동물, 기타 |
| 성격 | 재미와 공감을 위한 엔터테인먼트 콘텐츠 (운세·예언 아님) |

### 1.1 해결하려는 문제

기존 이름 궁합 서비스는 (1) 근거 없이 숫자만 보여주거나, (2) 같은 문장을 반복하거나,
(3) 전통 운세 사이트의 낡은 시각 언어를 쓴다. NAME SYNERGY는 **설명 가능한 규칙**과
**완성도 높은 에디토리얼 디자인**으로, 공유하고 싶은 현대적인 이름 리포트를 만든다.

### 1.2 성공 기준 (MVP)

- 처음 방문한 사용자가 30초 안에 입력을 마치고 결과를 볼 수 있다.
- 결과 화면의 모든 점수 옆에 "왜 이 점수인지" 근거가 있다.
- 서로 다른 이름 쌍은 실제로 다른 점수·근거·문장을 받는다. 같은 입력은 항상 같은 결과를 받는다.
- 결과 이미지 저장과 텍스트 복사가 모바일 Safari/Chrome에서 동작한다.

### 1.3 핵심 피처 (2026-11-09 확정)

| 구분 | 피처 | 역할 |
| --- | --- | --- |
| 핵심 1 | 근거가 보이는 이름 조화 지수 | 0~100점과 항목별 근거. 다른 궁합 서비스와의 가장 큰 차이 |
| 핵심 2 | 관계 유형 5종 | "우리는 RHYTHM TYPE" 같은 말하기 쉬운 정체성, 공유의 계기 |
| 핵심 3 | 세로형 공유 카드 | 확산 통로 |
| 지원 | 3축 분석 (발음·구조·의미) | 지수와 유형의 재료 |
| 지원 | 관계 스토리 | 결과를 읽을거리로 만듦 |
| 지원 | 30초 입력 | 필수는 이름 2개 + 관계 |
| 시그니처 | 이어 부르기 시각화 | 두 이름을 붙여 읽을 때 소리가 이어지는 모습을 그래픽으로 표현 (결과 페이지 대표 장면) |
| 시그니처 | 공유 소리 하이라이트 | 두 이름이 함께 가진 자음·모음 표시 |

### 1.4 일관성 원칙

같은 입력(이름, 한자, 의미, 관계)은 언제, 누가, 몇 번 분석해도 **완전히 같은 결과**(점수·유형·문장)를 받는다.
점수와 유형은 이름 순서(A×B / B×A)와도 무관하다. 자세한 규칙은 `ANALYSIS_RULES.md` 0장.

### 1.5 수집하지 않는 정보

성별은 받지 않는다. 분석에 쓰이지 않고, 불필요한 개인정보이며, 동성 커플·친구·동료 관계 등에서 불편을 만든다. 문장은 이름으로 부른다.

## 2. 사용자와 시나리오

- **커플/부부**: "우리 이름 잘 어울릴까?" 가볍게 확인하고 SNS 스토리에 공유.
- **친구**: 단톡방에서 서로의 이름 조합을 돌려보며 비교.
- **가족/동료**: 이름의 의미를 함께 이야기하는 대화 소재.

핵심 흐름: 메인 → 이름 입력 → 관계 선택 → (선택) 한자·의미 입력 → 분석 → 결과 확인 → 이미지 저장/공유.

## 3. 범위

### 3.1 포함 (PHASE 1)

반응형 웹, 한국어 UI, 두 사람 이름 입력, 관계 유형 선택, 한자·의미 입력(선택),
규칙 기반 분석 엔진, 이름 조화 지수, 관계 유형 분류, 개인화 리포트,
결과 이미지 저장, 결과 텍스트 복사, Web Share API 공유, 기본 SEO.

### 3.2 제외

로그인/회원가입, 결제, 서버 DB, 외부 AI API, 생년월일·출생시간, 사주·오행,
공개 URL 기반 결과 공유, 다국어, 한자 자동 뜻 풀이.

## 4. 페이지 요구사항

### 4.1 메인 페이지 `/`

목표: 짧은 시간 안에 서비스 가치를 전달하고 분석 시작을 유도한다.

| # | 섹션 | 요구사항 |
| --- | --- | --- |
| 1 | 헤더 | 워드마크 `NAME SYNERGY`, 우측 "분석하기" 링크 |
| 2 | 히어로 | 메인 카피 "두 사람의 이름에는 어떤 이야기가 숨어 있을까요?" / 서브 카피 "이름의 의미와 울림을 통해 두 사람의 특별한 조화를 발견해 보세요." / 주 CTA "이름 분석 시작하기" → `/analyze` |
| 3 | 서비스 소개 | 무엇을 하는 서비스인지 3줄 이내 + 이용 3단계(입력 → 분석 → 리포트) |
| 4 | 분석 항목 소개 | 발음의 조화 · 구조의 균형 · 의미의 조화 각각 한 줄 설명과 반영 비율(40/30/30) |
| 5 | 결과 예시 | 가상의 이름 쌍으로 만든 결과 카드 미리보기 (실제 엔진 출력 사용) |
| 6 | 관계 유형 | 5가지 유형 이름과 한 줄 설명 |
| 7 | 하단 | 브랜드 정보, "엔터테인먼트 콘텐츠" 안내, 개인정보 미저장 안내, 두 번째 CTA |

- 첫 화면(모바일 기준 스크롤 없이)에 워드마크, 메인 카피, CTA가 모두 보여야 한다.

### 4.2 이름 입력 페이지 `/analyze`

입력 항목

| 대상 | 필드 | 필수 | 규칙 |
| --- | --- | --- | --- |
| Person A / B | 이름 | 필수 | 완성형 한글만, 공백 제거 후 2~5자 (관계가 반려동물이면 Person B는 1~5자) |
| Person A / B | 한자 | 선택 | 한자(CJK 통합 한자)만, 최대 5자. 글자 수가 이름과 다르면 경고(분석은 가능) |
| Person A / B | 이름에 담긴 의미 | 선택 | 자유 텍스트, 최대 60자 |
| 공통 | 관계 유형 | 필수 (기본값 없음) | 연인 · 부부 · 친구 · 가족 · 동료 · 반려동물 · 기타 |

- **반려동물** 선택 시: Person A 라벨은 "나", Person B 라벨은 "반려동물"로 바뀌고, B 이름은 1글자도 허용한다("콩", "별"). 리포트는 반려동물 전용 호칭·템플릿을 쓴다.

UX 요구사항

- 두 사람 입력 영역을 색과 라벨(A/B)로 구분한다. 모바일은 세로 배치, 데스크톱(≥1024px)은 좌우 배치.
- 한자·의미는 "더 자세히 분석하기"로 접혀 있다가 펼칠 수 있다. 펼치지 않아도 분석 가능.
- 필수 항목이 비어 있거나 형식이 틀리면 분석 버튼이 비활성화되고, 필드 아래에 친절한 한국어 안내가 보인다.
  - 예: "이름을 입력해 주세요." / "이름은 한글 2~5자로 입력해 주세요." / "한자는 한자로만 입력해 주세요." / "두 사람의 관계를 선택해 주세요."
- 오류 문구는 입력을 건드린 뒤(blur) 또는 제출 시도 후에 보여준다. 처음부터 빨간 문구를 띄우지 않는다.
- 이름 외 개인정보를 요구하지 않는다. 입력 하단에 "입력한 이름은 저장되지 않아요" 안내.
- 같은 이름 두 개도 허용한다(동명이인). 이 경우 리포트에 동명 문구를 쓴다.

### 4.3 분석 처리

- 분석 버튼을 누르면 단계 문구를 순서대로 보여주는 짧은 진행 화면을 띄운다.
  1. 두 사람의 이름을 살펴보고 있습니다.
  2. 이름의 울림을 비교하고 있습니다.
  3. 이름에 담긴 의미를 연결하고 있습니다. (의미 자료가 없으면 생략)
  4. 두 사람만의 조화로운 이야기를 만들고 있습니다.
- 각 문구는 실제 엔진 단계(자모 분해 → 발음 → 의미 → 리포트)에 대응한다.
- 총 연출 시간은 최대 약 2초. 계산과 무관하게 길게 기다리게 하지 않는다. `prefers-reduced-motion`이면 즉시 이동.
- 결과는 `sessionStorage`에 저장 후 `/result`로 이동한다. 이름은 URL에 넣지 않는다.

### 4.4 결과 페이지 `/result`

서비스의 핵심 화면. 하나의 디지털 매거진 기사처럼 구성한다.

| # | 블록 | 내용 |
| --- | --- | --- |
| 1 | 커버 | 두 사람의 이름(A × B), 관계 유형 라벨, 헤드라인 문장 |
| 2 | 이름 조화 지수 | 0~100 정수, 시각화(링 또는 바), 등급 문구, "엔터테인먼트 지표" 안내 |
| 3 | 전체 요약 | 3~4문장 개인화 요약 |
| 4 | 발음의 조화 | 점수 + 세부 근거(모음 톤, 받침 리듬, 첫소리 질감, 이어 부르기, 공유 소리) |
| 5 | 구조의 균형 | 점수 + 세부 근거(글자 수, 소리 밀도, 받침 패턴) |
| 6 | 의미의 조화 | 점수 + 근거, 또는 "자료 부족" 상태와 입력 유도 |
| 7 | 관계 유형 | 유형 코드·제목·설명, 이 유형으로 분류된 이유 |
| 8 | 관계 스토리 | 두 이름을 연결한 짧은 스토리(템플릿 + 분석값) |
| 9 | 공유 | 이미지 저장, 텍스트 복사, 공유하기(지원 시), 다시 분석하기 |

- 결과 데이터가 없으면(새로고침 후 세션 만료, 직접 진입) 빈 상태 화면과 "이름 입력하러 가기" CTA를 보여준다.
- 반영된 가중치(재조정 포함)를 결과에 표시한다. 예: "의미 자료가 없어 발음 57% · 구조 43%로 계산했어요."

## 5. 분석 엔진 요구사항

상세 규칙은 `docs/ANALYSIS_RULES.md`. 요약:

- AI 추측이 아닌 명시적 규칙 기반. 모든 규칙은 코드와 문서에 같이 정의.
- 가중치: 발음 40% · 구조 30% · 의미 30%. 의미 자료가 없으면 의미를 제외하고 비례 재조정.
- 입력하지 않은 한자 뜻, 오행, 수리 정보를 만들지 않는다.
- 결정적 계산: 같은 입력 → 같은 점수, 같은 유형, 같은 문장.
- 관계 유형은 분석 수치로 결정하며 무작위 선택 금지.
- 관계(연인/친구 등) 선택은 **점수에 영향을 주지 않고** 문장의 호칭과 톤에만 반영한다.

## 6. 리포트 작성 요구사항

- 외부 생성형 AI 없이 분석값 + 사전 정의 문장 템플릿으로 조합한다.
- 문장 구성: 전체 조화 / 각 이름의 특징 / 두 이름이 만드는 이미지 / 관계의 강점 / 서로를 이해하는 메시지.
- 운명론·미래 예측·부정적 단정 금지. 낮은 점수도 "다름에서 오는 가능성"으로 표현한다.
- 향후 AI 연결 시에도 계산값과 근거를 먼저 만들고, AI는 문장 표현만 담당한다.

## 7. 공유 요구사항

- **이미지 저장**: 1080×1920 세로형 카드(PNG). 포함: NAME SYNERGY 브랜드, 두 이름, 조화 지수, 관계 유형, 핵심 메시지 1문장.
- **텍스트 복사**: 이름, 지수, 유형, 요약 1~2문장, 서비스 이름. 복사 완료 토스트.
- **공유하기**: `navigator.share` 지원 시 이미지 파일 또는 텍스트 공유, 미지원 시 버튼 숨김.
- 공개 URL 공유는 제외. 이름을 URL·외부 서비스로 보내지 않는다.

## 8. 개인정보 및 보안

- 회원가입 없음. 이름은 서버·DB에 저장하지 않고 브라우저 안에서만 처리한다.
- 결과는 탭 단위 `sessionStorage`에만 보관(탭을 닫으면 삭제).
- 외부 분석/광고 스크립트 미탑재(PHASE 1).
- API 키는 사용하지 않으며, 추후 필요 시 `.env.local` + 서버 측에서만 사용.

## 9. SEO 및 접근성

- 페이지별 `title`, `description`, Open Graph/Twitter 메타, `lang="ko"`, `robots.txt`, `sitemap.xml`, 파비콘, 기본 OG 이미지.
- `/result`는 개인 결과이므로 `noindex`.
- 텍스트 대비 WCAG AA(4.5:1) 이상, 모든 입력에 라벨, 키보드 접근 가능, 포커스 링 표시, 점수 시각화에 텍스트 대체.

## 10. 비기능 요구사항

- 모바일 우선. 기준 폭 375 / 768 / 1280px.
- Lighthouse(모바일) 성능·접근성·SEO 90점 이상 목표.
- 엔진 단위 테스트 필수(정상, 누락, 길이 초과, 한자 유무, 의미 유무, 점수, 유형 분류, 결정성).

## 11. 향후 확장

- PHASE 2: 생년월일·출생시간·양/음력, 검증된 사주 엔진, 이름+사주 결합 분석
- PHASE 3: NAME SCANNER — 인기 이름, 희소성, 한자·의미 검색

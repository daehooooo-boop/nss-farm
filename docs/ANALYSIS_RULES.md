# NAME SYNERGY — 분석 및 점수 계산 규칙

- 버전: rules v1.0 (PHASE 1)
- 최종 수정: 2026-11-08
- 구현 위치: `src/lib/hangul/`, `src/lib/analysis/`, `src/data/`
- 상수: 이 문서의 모든 가중치·임계값은 `src/lib/analysis/constants.ts`와 1:1로 일치해야 한다. 하나를 바꾸면 다른 하나도 같은 커밋에서 바꾼다.

> **이름 조화 지수는 과학적으로 검증된 궁합 점수가 아니다.**
> 두 이름의 소리·구조·의미 특징을 정해진 규칙으로 비교해 보여주는 엔터테인먼트 콘텐츠 지표다.

---

## 0. 원칙

1. **명시적 규칙**: AI 추측이나 통계 모델이 아닌, 이 문서에 적힌 규칙만 사용한다.
2. **결정성**: 같은 입력은 항상 같은 점수·유형·문장. 난수·시간 사용 금지.
3. **대칭성**: A×B와 B×A의 점수와 유형은 같다. (문장의 이름 순서만 다르다.)
4. **지어내지 않기**: 사용자가 입력하지 않은 한자 뜻·오행·수리·획수 정보를 만들거나 단정하지 않는다.
5. **자료 부족은 제외**: 분석할 수 없는 항목은 점수를 주지 않고, 나머지 항목으로 가중치를 재조정한다.
6. **근거 제공**: 모든 점수는 사람이 읽을 수 있는 근거 문장과 함께 반환한다.
7. **관계 유형(연인/친구 등)은 점수에 영향을 주지 않는다.** 문장의 호칭과 톤에만 반영한다.

## 1. 입력 정규화와 검증

| 필드 | 정규화 | 유효 조건 | 오류 문구 |
| --- | --- | --- | --- |
| 이름 | `NFC` 정규화 → 모든 공백 제거 | `/^[가-힣]{2,5}$/` | 비어 있음: "이름을 입력해 주세요." / 그 외: "이름은 한글 2~5자로 입력해 주세요." |
| 한자 | `NFC` → 공백 제거 | 비어 있거나 CJK 통합 한자(`\p{Script=Han}`) 1~5자 | "한자는 한자로만 5자까지 입력해 주세요." |
| 의미 | 앞뒤 공백 제거, 연속 공백 1칸 | 0~60자 | "의미는 60자 이내로 입력해 주세요." |
| 관계 | — | 6개 값 중 하나 | "두 사람의 관계를 선택해 주세요." |

- 한자 글자 수가 이름 글자 수와 다르면 **경고만** 표시한다("이름 글자 수와 한자 수가 달라요"). 분석은 진행한다.
- 이름은 성을 포함해 입력해도, 이름만 입력해도 된다. 입력된 문자열 전체를 분석한다. (UI에서 "두 사람 모두 같은 방식으로 입력하면 더 정확해요" 안내)
- 자모만 있는 입력(ㄱ, ㅏ), 영문, 숫자, 특수문자는 이름으로 받지 않는다.

## 2. 한글 음절 분해

완성형 한글 음절 코드 `c`(U+AC00~U+D7A3)에 대해:

```
idx  = c - 0xAC00
초성 = floor(idx / 588)            // 19종
중성 = floor((idx % 588) / 28)     // 21종
종성 = idx % 28                    // 0 = 받침 없음, 27종
```

예: `민` → ㅁ + ㅣ + ㄴ, `준` → ㅈ + ㅜ + ㄴ, `서` → ㅅ + ㅓ + (없음)

### 2.1 분류표

**모음 톤 (중성)**

| 분류 | 모음 | 값 |
| --- | --- | --- |
| 양성 (밝음) | ㅏ ㅐ ㅑ ㅒ ㅗ ㅘ ㅙ ㅚ ㅛ | +1 |
| 음성 (깊음) | ㅓ ㅔ ㅕ ㅖ ㅜ ㅝ ㅞ ㅟ ㅠ | −1 |
| 중성 (담백) | ㅡ ㅢ ㅣ | 0 |

**첫소리 질감 (초성 부드러움 값)**

| 분류 | 자음 | 값 |
| --- | --- | --- |
| 울림소리 | ㄴ ㄹ ㅁ ㅇ | 1.00 |
| 예사소리 | ㄱ ㄷ ㅂ ㅅ ㅈ | 0.60 |
| 목청소리 | ㅎ | 0.50 |
| 거센소리 | ㅊ ㅋ ㅌ ㅍ | 0.25 |
| 된소리 | ㄲ ㄸ ㅃ ㅆ ㅉ | 0.10 |

**복합 자모**: 이중모음 ㅘ ㅙ ㅚ ㅝ ㅞ ㅟ ㅢ는 자모 2개, 겹받침 ㄳ ㄵ ㄶ ㄺ ㄻ ㄼ ㄽ ㄾ ㄿ ㅀ ㅄ는 자모 2개로 센다.

### 2.2 이름별 특징값

이름의 음절 수를 `n`이라 할 때:

| 특징 | 정의 | 범위 |
| --- | --- | --- |
| `vowelTone` (모음 톤) | (양성 수 − 음성 수) / n | −1 ~ 1 |
| `openness` (열린 정도) | 받침 없는 음절 수 / n | 0 ~ 1 |
| `softness` (첫소리 부드러움) | 초성 부드러움 값의 평균 | 0.1 ~ 1 |
| `density` (소리 밀도) | 전체 자모 수 / n (초성1 + 중성1~2 + 종성0~2) | 2 ~ 5 |
| `pattern` (받침 패턴) | 음절별 O(열림)/C(닫힘) 배열 | 예: 민준 = C C |
| `sounds` (소리 집합) | 초성·중성·종성을 기본 자모로 풀어 만든 집합 (ㅇ 초성은 제외) | 집합 |

### 2.3 이름 특징 문장 (리포트용)

| 조건 | 표현 |
| --- | --- |
| vowelTone > 0.2 | 밝고 경쾌한 울림 |
| vowelTone < −0.2 | 깊고 차분한 울림 |
| 그 외 | 담백하고 맑은 울림 |
| openness ≥ 0.5 | 부드럽게 열리는 끝소리 |
| openness < 0.5 | 또렷하게 맺는 끝소리 |
| softness ≥ 0.75 | 둥근 첫소리 |
| softness < 0.5 | 선명한 첫소리 |
| 그 외 | 균형 잡힌 첫소리 |

## 3. 발음의 조화 (Phonetic) — 기본 가중치 40%

유사도 항목은 `점수 = 50 + 50 × 유사도`로 계산한다.
**바닥값 50**을 두는 이유: 소리가 다른 것도 "보완"으로 해석하는 서비스 관점이며, 차이는 점수보다 관계 유형(COMPLEMENT 등)으로 표현한다.

| 코드 | 항목 | 계산 | 점수 | 내부 비중 |
| --- | --- | --- | --- | --- |
| P1 | 모음 톤 | sim = 1 − \|tA − tB\| / 2 | 50 + 50·sim | 25% |
| P2 | 받침 리듬 | sim = 1 − \|oA − oB\| | 50 + 50·sim | 20% |
| P3 | 첫소리 질감 | sim = max(0, 1 − \|sA − sB\| / 0.9) | 50 + 50·sim | 20% |
| P4 | 이어 부르기 | flow = (연결(A→B) + 연결(B→A)) / 2 | 100·flow | 20% |
| P5 | 공유 소리 | J = \|soundsA ∩ soundsB\| / \|soundsA ∪ soundsB\| | 50 + 50·min(1, J / 0.5) | 15% |

**P4 연결값**: 앞 이름의 마지막 음절 받침 → 뒤 이름의 첫 초성

| 조건 (위에서부터 먼저 맞는 것) | 연결값 | 근거 문구 예 |
| --- | --- | --- |
| 앞 음절에 받침 없음 | 1.00 | 끝소리가 열려 있어 자연스럽게 이어져요 |
| 뒤 첫 초성이 ㅇ (소리 없음) | 1.00 | 받침이 다음 소리로 부드럽게 넘어가요 (연음) |
| 받침이 울림소리(ㄴ ㄹ ㅁ ㅇ) & 뒤 초성이 울림소리 | 0.85 | 울림소리끼리 만나 매끄럽게 이어져요 |
| 뒤 초성이 예사소리 또는 ㅎ | 0.60 | 짧은 쉼표가 생기며 이어져요 |
| 뒤 초성이 거센소리 또는 된소리 | 0.40 | 또렷한 끊김이 있는 리듬이에요 |

```
발음 점수 = 0.25·P1 + 0.20·P2 + 0.20·P3 + 0.20·P4 + 0.15·P5
```

## 4. 구조의 균형 (Structure) — 기본 가중치 30%

| 코드 | 항목 | 계산 | 내부 비중 |
| --- | --- | --- | --- |
| S1 | 길이 균형 | 음절 수 차이 0 → 100, 1 → 85, 2 → 65, 3 → 50 | 40% |
| S2 | 소리 밀도 | sim = max(0, 1 − \|dA − dB\| / 1.5) → 50 + 50·sim | 30% |
| S3 | 받침 패턴 | 두 패턴을 **끝에서부터** 맞춰 짧은 쪽 길이만큼 비교, 일치율 m → 50 + 50·m | 30% |

끝에서부터 맞추는 이유: 성을 포함하든 빼든 이름 부분(끝 음절)이 정렬되도록 하기 위함.

```
구조 점수 = 0.40·S1 + 0.30·S2 + 0.30·S3
```

## 5. 의미의 조화 (Meaning) — 기본 가중치 30%

### 5.1 분석 가능 조건

의미 분석은 **사용자가 입력한 의미 텍스트**로만 한다. 한자만으로는 뜻을 풀지 않는다.

| 상태 코드 | 조건 | 표시 | 점수 |
| --- | --- | --- | --- |
| `available` | 두 사람 모두 의미 입력 & 각각 1개 이상 의미 범주 인식 | 점수 + 근거 | 계산 |
| `none` | 두 사람 모두 의미 미입력 | "자료 부족 — 이름의 의미를 입력하면 분석할 수 있어요" | 제외 |
| `partial` | 한 사람만 입력 | "한 사람의 의미만 있어 비교할 수 없어요" | 제외 |
| `unrecognized` | 입력했지만 인식된 범주가 없음 | "입력한 의미에서 비교할 키워드를 찾지 못했어요" + 입력 원문 표시 | 제외 |

한자만 입력된 경우 상태는 위 표를 따르며, 추가로 "한자의 뜻을 함께 적어 주시면 의미를 분석할 수 있어요"를 안내한다.

### 5.2 의미 범주 사전

`src/data/meaningKeywords.ts`에 범주별 키워드를 둔다. 입력 텍스트에 키워드가 **포함**되면 해당 범주로 인식한다. 오탐을 줄이기 위해 키워드는 원칙적으로 2자 이상이며, 1자 키워드는 아래 표에 명시된 것만 허용한다.

| 범주 코드 | 이름 | 대표 키워드 (일부) |
| --- | --- | --- |
| `light` | 빛·밝음 | 빛, 밝, 환하, 햇살, 태양, 광명, 빛나 |
| `wisdom` | 지혜·배움 | 지혜, 슬기, 총명, 현명, 학문, 배움, 명석 |
| `virtue` | 어짊·덕 | 어질, 덕, 인자, 착하, 너그러, 선하 |
| `peace` | 평안·화목 | 평안, 편안, 평화, 화목, 안녕, 고요 |
| `strength` | 굳셈·용기 | 굳세, 강하, 용기, 용감, 씩씩, 튼튼 |
| `nature` | 자연·초목 | 나무, 숲, 꽃, 풀, 봄, 자연, 열매 |
| `water` | 물·바다 | 물, 바다, 강, 시내, 맑은 물, 샘 |
| `aspiration` | 큰 뜻·높음 | 하늘, 높, 큰 뜻, 크게, 우뚝, 뛰어나 |
| `beauty` | 아름다움 | 아름답, 고운, 곱, 예쁘, 빼어나 |
| `joy` | 기쁨·복 | 기쁨, 기쁘, 복, 행복, 즐거, 경사 |
| `growth` | 성장·번영 | 성장, 자라, 번영, 번성, 이루, 성공 |
| `integrity` | 바름·진실 | 바르, 곧, 정직, 진실, 의로, 참 |
| `love` | 사랑·은혜 | 사랑, 은혜, 따뜻, 다정, 아끼 |

허용된 1자 키워드: 빛, 덕, 숲, 꽃, 풀, 봄, 물, 강, 샘, 높, 곱, 복, 곧, 참.
(정확한 전체 목록은 코드가 기준이며, 이 표와 다르면 코드를 기준으로 문서를 갱신한다.)

### 5.3 보완 관계 범주쌍

서로 다른 범주라도 아래 쌍은 "서로를 채우는 의미"로 본다.

| 쌍 | 해석 |
| --- | --- |
| strength ↔ peace | 굳셈과 평안: 단단함이 고요함을 지켜 줌 |
| light ↔ nature | 빛과 초목: 빛이 자라게 함 |
| water ↔ nature | 물과 초목: 서로를 살림 |
| wisdom ↔ virtue | 지혜와 어짊: 판단과 마음의 균형 |
| aspiration ↔ integrity | 큰 뜻과 바름: 방향과 기준 |
| beauty ↔ love | 아름다움과 사랑: 바라봄과 아낌 |
| growth ↔ joy | 성장과 기쁨: 이룸과 누림 |

### 5.4 계산

```
shared = |범주A ∩ 범주B|
comp   = 두 사람 사이에 성립하는 보완 쌍의 수 (공유 범주끼리는 제외)

의미 점수 = min(100, 55 + 20·min(shared, 2) + 12·min(comp, 2) + 한자보너스)
한자보너스 = 두 사람 모두 한자를 입력했고 같은 한자 글자가 1개 이상이면 5, 아니면 0
```

- 공유도 보완도 없으면 55점: "서로 다른 방향의 의미를 가진 두 이름"으로 해석한다.
- 한자보너스는 "같은 글자를 나눠 가졌다"는 사실만 사용하며, 그 글자의 뜻은 풀지 않는다.

## 6. 이름 조화 지수 (종합)

### 6.1 가중치와 재조정

| 항목 | 기본 가중치 | 의미 제외 시 |
| --- | --- | --- |
| 발음의 조화 | 40% | 40 / 70 = 57.1% |
| 구조의 균형 | 30% | 30 / 70 = 42.9% |
| 의미의 조화 | 30% | 제외 |

```
사용 가능 항목 집합 U
w'_i = w_i / Σ_{j∈U} w_j
이름 조화 지수 = round( Σ_{i∈U} w'_i · score_i )      // 정수 0~100, 반올림
```

결과 화면에 실제 적용된 가중치를 표시한다(소수 첫째 자리 반올림 → 정수 %).

각 세부 점수(P1~P5, S1~S3, 의미)는 계산 중에는 소수를 유지하고, 표시할 때만 정수로 반올림한다.

### 6.2 등급 문구

| 지수 | 문구 |
| --- | --- |
| 90 ~ 100 | 눈부신 조화 |
| 80 ~ 89 | 깊은 조화 |
| 70 ~ 79 | 편안한 조화 |
| 60 ~ 69 | 흥미로운 조화 |
| 0 ~ 59 | 새로운 조화 |

낮은 점수에도 부정적 문구를 쓰지 않는다.

## 7. 관계 유형 분류

### 7.1 판별 지표

```
Sim  = 평균(simP1, simP2, simP3, simS2)     // 두 이름의 소리·구조 유사도, 0~1
Flow = P4의 flow                            // 0.4~1
T    = 이름 조화 지수
```

### 7.2 규칙 (위에서부터 먼저 만족하는 유형)

| 순서 | 유형 | 조건 | 의미 |
| --- | --- | --- | --- |
| 1 | **SYNERGY TYPE** | T ≥ 88 그리고 Flow ≥ 0.85 | 함께할 때 새로운 가능성이 만들어지는 관계 |
| 2 | **RHYTHM TYPE** | 음절 수 같음 그리고 받침 패턴 일치율 ≥ 2/3 그리고 simP1 ≥ 0.75 | 비슷한 리듬과 분위기를 가진 관계 |
| 3 | **HARMONY TYPE** | Sim ≥ 0.75 | 자연스러운 조화를 이루는 관계 |
| 4 | **COMPLEMENT TYPE** | Sim < 0.55 | 서로 다른 특징을 보완하는 관계 |
| 5 | **BALANCE TYPE** | 그 외 | 서로의 균형을 맞추는 관계 |

- 분류 결과와 함께 **어떤 조건으로 분류되었는지** 근거 문장을 반환한다.
  예: "두 이름 모두 3음절에 받침 패턴이 같고 모음 톤도 닮아 RHYTHM TYPE으로 분류했어요."
- 임계값은 STEP 5에서 대표 이름 쌍 샘플(약 200쌍)로 분포를 확인해 보정할 수 있다. 목표: 각 유형이 샘플의 10% 이상. 보정 시 이 표와 `constants.ts`를 함께 수정하고 변경 이력에 남긴다.
- 유형 정의(제목, 설명, 강점, 스토리 템플릿)는 `src/data/relationTypes.ts`에 둔다.

## 8. 리포트 문장 조합

### 8.1 구성

| 블록 | 사용하는 값 |
| --- | --- |
| 헤드라인 | 유형, 등급 |
| 전체 요약 | 지수, 등급, 가장 높은 세부 항목, 가장 낮은 세부 항목 |
| 각 이름의 특징 | 2.3의 특징 문장 |
| 두 이름이 만드는 이미지 | 모음 톤 조합(밝음+깊음 등), 이어 부르기 |
| 관계의 강점 | 유형별 강점 템플릿 + 최고 항목 |
| 서로를 이해하는 메시지 | 유형별 메시지 템플릿 + 가장 차이가 큰 특징 |
| 관계 스토리 | 유형별 스토리 템플릿 + 두 이름 + 공유 소리/의미 |

### 8.2 템플릿 규칙

- 템플릿 변수: `{nameA}`, `{nameB}`, `{pair}`(관계 호칭), `{score}`, `{grade}`, `{type}`, `{sharedSound}`, `{sharedMeaning}` 등. 조사는 받침 유무로 자동 선택한다(`은/는`, `이/가`, `을/를`, `과/와`, `(이)랑`).
- 관계 호칭: 연인·기타 → "두 사람", 부부 → "두 분", 친구 → "두 친구", 가족 → "두 가족", 동료 → "두 동료".
- 같은 조건에 여러 표현 변형이 있을 때는 **입력 기반 해시**로 고른다:
  `seed = FNV-1a 32bit( 정렬된 [이름A, 이름B].join("|") + "|" + 관계 )`, `variant = (seed + 블록번호) % 변형 수`.
  난수가 아니므로 같은 입력은 같은 문장을 받고, 다른 입력은 다른 문장을 받을 수 있다. 유형·점수 결정에는 해시를 쓰지 않는다.
- 금지 표현: 운명, 천생연분, 반드시, 영원히, 헤어짐, 불운, 흉 등 단정·예언·부정 표현.

### 8.3 특수 케이스

- 두 이름이 같음: "같은 이름을 나눠 가진 {pair}" 문구 사용. 점수는 규칙대로 계산.
- 의미 자료 부족: 의미 관련 문장 블록을 생략하고 "의미를 더하면 이야기가 더 풍부해져요" 안내.

## 9. 출력 데이터 구조 (요약)

```ts
type AnalysisResult = {
  version: "1.0";
  input: { a: PersonInput; b: PersonInput; relation: Relation };
  features: { a: NameFeatures; b: NameFeatures };
  sections: {
    phonetic: SectionScore;   // score, items[P1..P5], reasons[]
    structure: SectionScore;  // score, items[S1..S3], reasons[]
    meaning: SectionScore | { status: "none" | "partial" | "unrecognized"; message: string };
  };
  weights: { phonetic: number; structure: number; meaning: number | null };
  total: number;              // 0~100
  grade: string;
  type: { code: RelationTypeCode; reason: string };
};
```

리포트(`lib/report`)는 `AnalysisResult`만 입력으로 받아 문장을 만든다.

## 10. 테스트 기준

| # | 테스트 | 기대 |
| --- | --- | --- |
| 1 | 정상 입력 | 0~100 정수, 유형 1개, 모든 섹션 근거 존재 |
| 2 | 이름 누락 | 검증 실패, "이름을 입력해 주세요." |
| 3 | 길이 1자 / 6자, 영문, 자모 | 검증 실패, 길이 안내 문구 |
| 4 | 한자만 입력 | 의미 `none`/`partial`, 의미 가중치 제외, 한자 뜻 문장 없음 |
| 5 | 의미 입력 | 범주 인식, 의미 점수 계산, 가중치 40/30/30 |
| 6 | 결정성 | 같은 입력 100회 → 동일 결과 |
| 7 | 대칭성 | A×B와 B×A의 지수·유형 동일 |
| 8 | 차별성 | 서로 다른 이름 쌍 다수 → 지수·근거가 모두 같지 않음 |
| 9 | 유형 분류 | 각 유형의 조건을 만족하는 고정 예시 쌍이 해당 유형으로 분류 |
| 10 | 가중치 재조정 | 의미 제외 시 가중치 합 = 1 |
